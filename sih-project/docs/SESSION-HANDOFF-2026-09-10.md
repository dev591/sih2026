## 1. Project shape, in one paragraph

PRAMANA is a digital-twin engine health monitoring system for SIH26054
(DRDO problem statement): a simulated turbocharged aero-diesel (VRDE 180 hp,
config also supports a Rotax 914) runs a mean-value engine model (MVEM) on
the backend, streams telemetry over WebSocket, and a React/Three.js frontend
renders a 3D engine twin plus a ground-control-station dashboard. The core
claim is **parity-space fault detection**: an 11-element residual vector
ρ₁–ρ₁₁ is derived from redundant physical relations (not raw sensors), is
nominally zero, and departs in a fault-specific *pattern* that an incidence
matrix and an ML stack both interpret. Team: BE-1 (physics/backend), BE-2
(ML), frontend (this session's primary work), all pushing to the same
branch.

Three people/roles, three codebases, one shared contract:
`docs/spec/residual-spec.md` (physics) + `docs/spec/telemetry-schema.md`
(wire format) + `ml/incidence.py` / `frontend/src/analysis/incidence.ts`
(fault→residual mapping, must stay byte-identical across languages).

## 2. Backend / physics (BE-1's code, reviewed and partially fixed)

### 2.1 Bugs found and fixed (commit `3488fa6`)

- **`Q_LHV_J_per_kg: 43.0e6` in both engine YAMLs parsed as a STRING, not a
  float.** PyYAML's safe-float regex requires a signed exponent (`e+`/`e-`);
  without it `43.0e6` is not recognized as numeric. This silently broke
  every `MVEM.step()` call — even BE-1's own `verify.py` was failing.
  Fixed to `43.0e+6` / `43.5e+6` in `config/engine_vrde_180.yaml` and
  `config/engine_rotax_914.yaml`.
- **`parity/sigma_generator.py` was a 0-byte stub.** Implemented it: samples
  the healthy plant/twin pair across 9 operating points (sea level→critical
  altitude, idle→full throttle), computes per-channel σ, writes
  `backend/config/sigma_vector.json`. Before this, `main.py` silently fell
  back to `sigma=[1.0]*11`, meaning every ρ was in raw physical units, not
  σ-units.
- **ρ₃ (Path 4 / intake restriction) had a placeholder formula
  byte-identical to ρ₁** — dead today (no engine config enables
  `parity_paths.intake_restriction`) but would silently double-count Path 1
  as Path 4 if ever flipped on. Replaced with `NotImplementedError` citing
  the spec's "never fabricate ρ₃" rule.

### 2.2 Critical unresolved bug: the air path is structurally collapsed

**This is BE-1's Day 2 blocker, documented in
`docs/team/BE-1-DAY2-PLAN.md` and `docs/qa/known-issues.md`.**

At 18,000 ft / 72% throttle (the operating point `main.py` hardcodes):
`p_im` sits at **exactly** `p_atm × 0.4` (its clamp floor) and `turbo_rpm`
at **exactly** 95 rpm (its floor). Not converged — pinned. Result: the
engine makes **2.2 kW of a rated 134.2 kW**, settling at **1564 rpm**
against the frontend's expected `cruiseRpm: 3580`.

Three causes, all in `backend/twin/mvem.py`:
1. **Turbo shaft integrates explicit-Euler at `J_tc=2e-5`, `h=0.01s`** —
   numerically stiff and unstable.
2. **Absorbing state:** once `p_im < p_atm`, both pressure ratios clamp to
   1.0, which zeroes `P_turb` **and** `P_comp` simultaneously, so
   `dw_tc/dt = 0` exactly. The turbo can never respool — this is why the
   simulation freezes rather than merely running slow.
3. **`m_c = m_a * (w_tc/w_tc_nom)` is not a real compressor map** — it's
   slaved to `m_a`, so at nominal turbo speed `m_c ≡ m_a` and
   `dp_im/dt ≡ 0` identically. This is the more important bug: since
   **ρ₁ = ṁ_SD − ṁ_C** (speed-density vs compressor path, per
   `residual-spec.md`), slaving `m_c` to `m_a` leaves ρ₁ with **zero
   independent information** — compressor fouling can never be detected.

**Root cause, not BE-1's fault:** the three lookup tables the YAML
references (`compressor_map.csv`, `lookup_eta_v.csv`, `prop_cp_map.csv`)
**do not exist in the repo**. BE-1 had no real compressor map to code
against, so a placeholder was unavoidable.

**Objective, falsifiable test for whether this is fixed:** re-run
`python3 -m parity.sigma_generator` — σ(ρ₁) and σ(ρ₅) must come off the
1e-3 floor (see §2.3). This was independently confirmed by measurement, not
just code-reading.

### 2.3 σ-vector diagnostic — which residual channels currently carry signal

Generated by `sigma_generator.py` from the (currently broken) physics:

| Channel | σ | Status |
|---|---|---|
| ρ₁ (speed-density vs compressor) | **0.001** | **DEAD** — on the clamp floor, see §2.2 |
| ρ₂ (speed-density vs fuel/λ) | 0.998 | alive |
| ρ₃ (intake restriction) | — | correctly null (unthrottled FADEC, no Path 4 sensor) |
| ρ₄ (energy closure) | 1.105 | alive |
| ρ₅ (power / propeller dynamometer) | **0.001** | **DEAD** — no propeller law implemented, `T_load` is a made-up quadratic |
| ρ₆–ρ₉ (per-cylinder thermal, blended CHT+EGT) | 0.28–0.32 | alive |
| ρ₁₀ (oil pressure) | **0.222 (= pure sensor noise)** | **DEAD** — `oil_press_bar`/`oil_temp_C` are hardcoded constants (3.42 bar, 96.3°C), no oil model exists at all |
| ρ₁₁ (0.5-order crank ripple) | 0.160 | alive |

**Net: 4 of 11 residual channels currently carry zero real signal.** This
matters enormously for the ML layer (see §4) because the models train on
all 11 dimensions as if they were all informative.

### 2.4 Other backend facts worth knowing
- Faults are injected as **parameter perturbations** (never signal spikes)
  — `cd_inj`, `eta_c_scale`, `hA_scale`, `f_fric_scale` passed into
  `plant.step()`. The hooks exist in `main.py` but nothing writes to them
  yet — **the live backend cannot currently respond to a fault-injection
  command from the frontend** (see §3.3, FE-2).
- Sensor faults go through `measurement.py` **only** (never touch plant
  state) — this asymmetry is correctly implemented and is the whole
  sensor-vs-engine discriminator.
- `main.py`'s WebSocket is **send-only** — no receive loop. This is the
  other half of the FE-2 issue.
- `backend/ml/` (BE-2's first, wrong-location attempt) does not exist
  anymore — canonical location is `sih-project/ml/` (top-level, sibling of
  `backend/` and `frontend/`).

  past the end of the report reached the canvas behind it and orbited the

**FE-2 (open, documented not fixed) — Fault Console has no effect while

## 4. ML layer (BE-2's code, reviewed and heavily fixed)

### 4.1 What BE-2 delivered (commit `1a94518`)
`sih-project/ml/`: M1 (physics-guided residual estimator, MVEM stub + MLP
correction), M2 (LSTM autoencoder, anomaly detection), M3 classifier
(1D-CNN fault ID) + M3 RUL (quantile heads p10/p50/p90 + physics head),
novelty projection (SVD-based null-space detector), UKF (8-parameter joint
state estimation), N-CMAPSS benchmark notebook. Trained on **synthetic**
residuals (`ml/data/synthetic.py`), deliberately **not** on BE-1's (broken)
MVEM output — a good call, made explicitly and stated in the commit
message. Weights committed, all under 500KB, no LFS needed.

BE-2's own commit message **disclosed its own limitations honestly** — rare
and worth noting as a positive signal about that collaborator.

### 4.2 Bugs found by actually running the pipeline (commit `7f99080`)

**UKF — every health parameter returned an IDENTICAL value regardless of
which fault was injected.** Root cause in `ml/ukf/filter.py`,
`_sigma_points()`: added the *entire* `sqrt(diag(P))` vector to every sigma
point instead of one column of the Cholesky factor per point. This
collapsed 17 sigma points down to effectively 3, and the filter could only
move θ along the all-ones direction. Fed a compressor-only fault signature
for 60 steps: all 8 parameters came back at 1.063 (identical). Fixed by
using `S[:, i]` (i-th column of `cholesky((n+λ)P)`) per sigma point pair.
Also fixed: `alpha=1e-3` made `(n+λ)≈8e-6` with ~10⁶ sigma weights
(numerically hopeless) — changed to `alpha=1.0`, valid since the
observation model is near-linear in θ. Also: the Kalman gain wasn't masked
for missing channels, so it picked up spurious "information" from ρ₃ **on
every single step** (ρ₃ is always null on the VRDE).

**Three UKF sensitivity signs were inverted** against the incidence matrix
(hA and both injector-related terms). The filter was driving `cd_inj`
*above* nominal for a fouling signature — i.e. reporting an injector
flowing *better* than new while diagnosing a clog. Fixed. **Verified
after both fixes**, one fault signature at a time, 80 steps each:

| Injected | Identified parameter | Others |
|---|---|---|
| turbo degradation | η_c → 0.667 | nominal |
| injector fouling cyl 2 | cd_inj₂ → 0.329 (cd₁/₃/₄ ≈ 0.91) | nominal |
| cooling fouling | hA → 0.561 | nominal |
| bearing wear | f_fric → 1.449 | nominal |
| healthy | — | all 1.000 |

This is the difference between θ being a meaningful "compressor efficiency
0.87, down from 0.94" statement (the architecture's own stated goal) and it
being three decimal places of noise.

**No `healthy` class in M3.** `FAULT_NAMES` has 13 entries, none of them
"healthy" — so the classifier always names *some* fault, even on a fully
healthy engine (observed: `fuel_filter_clog` at p=0.385 while every limit
was green — exactly the frame the demo opens on). Fixed by gating M3's
output on M2's persistence-rule alarm: until detection actually fires, the
reported finding is `"healthy"`. Verified: silent through step 5, then
`injector_fouling p=0.937` once persistence triggers at step 15.

**`physics_h` returned `float('inf')` when no damage rate was available**
(which is always, until BE-1's Day-3 damage integrator exists). Two
problems: (1) `heads_disagree` was permanently `True`, and (2) `Infinity`
is **not valid JSON** — `JSON.parse` would throw in the browser, breaking
the dashboard. Fixed: returns `None`/`null` when the head has nothing to
integrate ("has not reported" rather than "reports infinite life").
Frontend `types/telemetry.ts` (`physics_h: number | null`),
`components/Panels.tsx`, and `components/FlightReport.tsx` all updated to
handle the null case; build verified clean.

**The "two independent mechanisms agree" claim was circular, not
independent.** Training samples in `synthetic.py` were generated *exactly
along* incidence-matrix columns, and the "independent" cosine matcher
scores against those same columns — so agreement was a mathematical
identity, not evidence. An evaluator asking "how was the classifier
trained?" would immediately see this. Fixed the generator to add per-sample
**direction jitter** off the nominal column, so the classifier learns a
region rather than reproducing the matrix. **Measured** (not assumed)
agreement after the fix: matcher-vs-classifier agree **37.9%** of the time
(window-mean ρ; 27% on a single noisy frame), and the matcher alone scores
32.7% top-1 against the classifier's 62.4%. Corrected the "independent
mechanisms" language in `docs/pitch/demo-script.md` and
`docs/backend/ML-DEEP-DIVE.md` to say "two mechanisms of different kinds,
not statistically independent" and to cite the measured agreement rate
instead of claiming a guarantee.

**Held-out evaluation didn't exist.** BE-2's reported "0.903 accuracy" was
**training-set** accuracy — measured on the same loader the model fit, with
no held-out fault split anywhere in the dataset class. Added
`faulty_val` (`SyntheticResidualDataset`, separate RNG stream, never
trained on) plus a full confusion-matrix report
(`ml/weights/m3_classifier_report.json`). True generalization figure:
**0.624 top-1 / 0.816 top-2** (n=3100) — see §4.3 for why this number is
expected to be low and what changes it.

**SPEC-1 — `detonation` and `egt_sensor_drift` have byte-identical
incidence rows.** Not a bug in any one person's code — faithful to
`residual-spec.md`'s own table, mirrored correctly in both `ml/incidence.py`
and `frontend/src/analysis/incidence.ts`. But structurally, **no method
built on that matrix can ever separate them**, and this particular pair
straddles the exact component-vs-instrumentation line the demo's 3:00 beat
is built on. Undeclared, this is a path to confidently telling a commander
"instrumentation fault, engine is fine" while the engine detonates.

Two-part fix:
1. **Detection layer:** `ml.incidence.inseparable_groups()` derives
   structurally-identical fault groups directly from the matrix (not
   hand-asserted). `ml/inference.py` now refuses to assert
   `is_sensor_fault` when the top hypothesis falls in such a group, forces
   `ambiguous: true`, and returns `inseparable_from` naming the other
   candidate(s). Verified: fed the shared signature, got
   `is_sensor_fault: False, ambiguous: True, inseparable_from:
   ['detonation']` instead of a confident (and possibly wrong) call.
2. **Root-cause fix (later in session, uncommitted as of writing — see
   §5):** gave `detonation` a non-zero ρ₁₁ entry (`+2`). Physically
   justified: detonation is a combustion abnormality that rings the
   structure and should appear in the 0.5-order crank ripple channel; a
   drifting thermocouple does not move ripple at all. This is a genuine
   physics distinction the original table simply omitted, not an invented
   number. **Changed in all three mirrors simultaneously** —
   `ml/incidence.py`, `frontend/src/analysis/incidence.ts`,
   `docs/spec/residual-spec.md` §3/§4 — with the rationale recorded in the
   spec itself. `inseparable_groups()` now returns `[]` (this is the
   regression test). **Measured effect: raises the theoretical maximum
   achievable accuracy (see §4.3) from 0.643 → 0.687.**

**Backend integration.** `main.py` previously didn't import `ml/` at all —
all health-frame fields (anomaly/diagnosis/rul/theta/novelty) were
hardcoded stub constants. Added a per-connection `InferencePipeline`
instance (§2.4-style isolation — two judges on two tabs must not share
state), which overlays real model output onto the stub blocks each frame.
Guarded with a try/except import so a machine without `torch` installed
still serves schema-valid frames (demo-script.md's fallback-layer
requirement).

**N-CMAPSS notebook loader was wrong for the real file format** — assumed
`f['train']`/`f['test']` HDF5 groups of named columns; the actual file
(confirmed after downloading it, see §4.4) stores flat parallel arrays
(`W_dev`, `X_s_dev`, `Y_dev`, `A_dev`, plus `*_var` name arrays). Would have
crashed the instant the multi-hour download finished. Rewritten for the
real layout, bounded by unit count + stride so it can't exhaust memory
(this machine OOM-killed two background jobs during this session), trains
on `X_s` (measured sensors) **only** — `X_v` (virtual/simulator-only
channels) and `T` (ground-truth health parameters) are deliberately
excluded, since training on `T` would be leakage (it's the literal answer)
and would produce an indefensible score. Notebook prints `REAL_DATA =
True/False` beside every result so a synthetic-stand-in number can never
be mistaken for a real one.

### 4.3 The accuracy investigation — full detail, this is the important part

**Question asked: "can accuracy reach 90–99%?" Answer: no, not honestly,
and here is the proof rather than an assertion.**

Computed the **oracle ceiling**: the accuracy of a perfect classifier that
knows the exact generative process (nearest-signature classification with
zero model error). This is a hard upper bound — no real model can exceed
it.

- Oracle ceiling on the task as BE-2 originally built it: **0.645**.
- Our trained model: **0.624** — i.e. already within 2 points of the
  ceiling on that task definition.

Tested every lever that does **not** change what the task fundamentally
is:
| Lever | Ceiling |
|---|---|
| Longer observation window (32→512 steps) | 0.644 → 0.658 |
| Higher fault severity (2–6σ → 8–14σ) | 0.644 → 0.657 |
| Both combined | 0.659 |

None of these move it meaningfully. Isolated the actual dominant variable:
**`direction_jitter`**, the parameter added to fix the circularity bug
(§4.2). This single invented constant turned out to set the ceiling almost
entirely:

| jitter | ceiling |
|---|---|
| 0.00 | 0.871 |
| 0.10 | 0.867 |
| 0.20 | 0.799 |
| **0.30 (the value used)** | **0.644** |
| 0.40 | 0.497 |

**Attempted to replace the guess with a measurement.** Built
`ml/data/measure_jitter.py`: perturbs the actual MVEM parameter for each
fault type (via BE-1's real `twin/mvem.py` + `parity/residuals.py`
pipeline, the same code path `main.py` runs), measures the angle between
the resulting real residual vector and its nominal incidence column.
**Result: inconclusive.** Only the two pure sensor faults (CHT/EGT drift,
which bypass the physics entirely — measurement-layer only) produced
sensible numbers (0.19, 0.26). Every component fault (injector, turbo,
bearing) either failed outright or returned nonsense (ring_wear → 4.59),
because §2.2's collapsed air path means perturbing an injector barely moves
anything physically real. **Explicitly declined to lower the jitter based
on this evidence** — it would have bought +8.5 points (0.643→0.728 at
jitter 0.25) but the only two data points that worked are the structurally
simplest case and would bias the estimate optimistic. This is recorded as
an open, physics-blocked item, not resolved by picking a convenient number.

**Separately found and fixed the SPEC-1 incidence degeneracy** (§4.2) —
this alone raised the ceiling **0.643 → 0.687**, and is physically
justified rather than invented, so it *was* applied.

**Investigated a second, larger lever, NOT applied — awaiting the user's
decision.** `backend/parity/residuals.py` currently blends two independent
per-cylinder thermocouple readings into one number:
`rho6_9 = 0.45*dCht + 0.55*dEgt`. Splitting CHT and EGT into separate
residual channels (11→15 dimensions) was tested and would raise the oracle
ceiling **0.687 → 0.805** (at jitter 0.30; higher still at lower jitter).
**Explicitly NOT implemented**, for reasons discussed with the user:
- Requires per-fault CHT/EGT split weights that would currently have to be
  *invented* (same category of guess as the jitter problem this whole
  investigation was trying to eliminate).
- Breaks the frozen contract simultaneously across `residual-spec.md`,
  `telemetry-schema.md`, `ResidualVector`, `N_RESIDUALS=11` everywhere,
  every committed model weight (`input_dim=11`), sigma_vector.json, the
  residual heatmap UI, and the novelty projection.
- Two days from judging is the wrong time for a cross-layer contract
  change neither BE-1 nor BE-2 has been consulted on.
- **Recommended instead as a roadmap/architecture slide**: "we measured
  that blending two independent thermocouples costs ~12 points of
  achievable accuracy" is a strong demonstration of engineering rigor
  without the execution risk.

**As of this writing, a retrain is IN PROGRESS** (background process,
`ml/train.py`, unbuffered log at the path noted at the end of this file)
using: (a) the fixed incidence matrix (ceiling now 0.687, up from 0.643),
and (b) an improved M3 classifier architecture — see §4.5. **The actual new
held-out accuracy number was not yet available when this file was
written.** Check the training log / re-run
`python3 -m ml.train` and read `ml/weights/m3_classifier_report.json`
for the current number. Expected range based on the ceiling and the
architecture improvement: roughly **0.65–0.70**, NOT 0.80+ (that would
require the CHT/EGT split, which is deliberately not applied).

### 4.5 M3 classifier architecture change (uncommitted improvement, in the
retrain running as of this writing)

`ml/m3_classifier/model.py`, `ResidualCNNEncoder`:
- **Added input scale-normalization** (`x = x / x.norm(...)`) before the
  conv layers. Rationale: fault *identity* lives in the **direction** of ρ
  (per `residual-spec.md`: "identified by which relations depart and with
  what sign, not by how far"); magnitude only encodes severity (2–6σ in
  training). The un-normalized model was wasting capacity learning
  scale-invariance it should never have needed.
- Widened channels 32→48, 64→96, added `BatchNorm1d` after each conv.
- Training: LR schedule was previously cosine-annealed to zero by epoch 40
  while loss was still visibly falling — increased to 120 epochs, `lr=2e-3`.
- **Verified as a genuine improvement, not just more capacity**: at epoch
  40 (same point old training stopped), new architecture's loss was 0.811
  vs old architecture's final loss of 0.949. At epoch 60: 0.659. At epoch
  70: 0.609 (in the aborted comparison run). This is real, not noise.
